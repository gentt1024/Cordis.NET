## Candidate Profile and package reinstall slice, 2026-10-22

S4 follows fixed candidate `687f282e8625c6b8d11ff58211a90524be2e4317`, including the app-boot profile-resolution and HMR package-reload suites. The formal behavior lock remains `639ed015397290b3745d163aafe02ffee4aa3f84`; the historical source inventory is unchanged. This is another scoped candidate exception.

The native deployment test map records the S4 exception explicitly: historical case `U-dc7d7920be57ad34` no longer claims complete assertion correspondence because local removal is now allowed and Profile metadata changes are scope-dependent. The original case and source inventory remain intact; its native successors are still executed by the mapping gate.

`DeploymentPackageResolver.ValidateReplacement` checks a complete successor without publishing it. `Replace` validates and publishes atomically, invalidating resolution caches only on success. Profile mappings, local names and linked roots may disappear. A retained profile mapping may change version or declarer in the same canonical directory and scope. Installation mappings remain fixed; a new local override of a published mapping is refused. A retained directory move requires restart. A removed linked root may later return at another target, but changing a retained link target remains a native restart boundary.

Profile reconciliation stops dropped topmost rows and groups while the old resolution is still published, waits for their cleanup, publishes the successor and reconciles the new composition. A publication failure restores the previous row structure and order while preserving the original error. Unconfirmed cleanup prevents overlapping recovery. Newly selected bundle row IDs enter the required set; as in the existing audit, absent and disabled rows are ignored. Other unchanged historical inactive entries remain warnings. Failed imports can retry after dependencies become available.

The standard CLR hot-upgrade path is removal followed by installation. Removal checks already loaded exports without importing inactive modules. A direct Fiber or an entry outside the removed bundle prevents removal with `unmanaged-plugin` before persistent edits. After owned rows settle, the toolchain unregisters exports and releases the package mapping, and the session publishes the removal. Reinstallation gets a fresh module identity and dependency closure. Disabled installation publishes its mapping without activating rows. Failed activation keeps the saved installation and selection visible for repair, removal and retry.

Stable artifacts remain immutable. Same-version reinstallation may reuse an existing directory only after receipt and identity verification and equality of every prepared relative filename and hash. A valid but different tree returns `package-moved`; incomplete or tampered receipts remain integrity failures. No DLL, dependency, resource or generated scaffold file is excluded. New SDK preparation disables scaffold debug output so identical preparations can have identical content; historical outputs that differ still require another exact version or explicit offline removal. Retained files stay available to existing delegates, Workers and other processes.

Direct updates of an installed identity still save a separate version for restart and leave the current route unchanged. This preserves the native immutable-generation adaptation; the candidate manager also requires removal before an HMR reinstall. Node's in-place package writes, private ESM/CJS cache eviction and filesystem marker clocks are not adopted. Changes to explicitly host-owned development modules continue through the S3 replacement callback and host dependency graph. Profile refresh does not infer a CLR reverse dependency graph or hot-replace installation-owned host assemblies. Native AOT code changes still require republishing.

Public API changes: `ProfileSession.RefreshAsync` now returns `Task<ProfileReloadResult>` with inactive-entry warnings, pending module identities and a profile-wide restart reason. `ConfigurationChange`, `PackageChange` and `PluginManagerChange` add nullable `RestartReason`; generated standard clients derive the same field from the declaration model. `DeploymentRestartRequiredException` exposes `Reason`. CLR and package toolchains expose `GetLoadedModulesAsync`; wrappers must forward it when they retain loaded modules. Reasons are `no-hmr`, `package-moved`, `host-module`, `unmanaged-plugin` and `module-comparison`; a global reason takes precedence over a pending-module reason. Current native Profile refusals use the global reason, and do not manufacture Node-style pending module lists. `no-hmr` means no coordinated lifecycle owner, not disabled automatic file watching. Existing callers must rebuild for the changed refresh return type and wire schema. See [validation](validation.md) and [artifact ownership](clr-artifacts.md).

## Candidate DSH 0.2.1 admission slice, 2026-10-22

The first slice implements plugin requirement admission from candidate DSH `687f282e8625c6b8d11ff58211a90524be2e4317` (0.2.1-rc.2). The formal behavior lock remains `639ed015397290b3745d163aafe02ffee4aa3f84` (0.2.0-rc.2). This is an explicit, scoped upgrade exception to that baseline, not a claim of complete 0.2.1 compatibility. Other candidate slices, including HMR and Remote authorization, remain separate work.

The candidate [evaluator](https://github.com/deepseek-ai/deepseek-harness/blob/687f282e8625c6b8d11ff58211a90524be2e4317/packages/boot/app-boot/src/plugin-compatibility.ts) and its [original tests](https://github.com/deepseek-ai/deepseek-harness/blob/687f282e8625c6b8d11ff58211a90524be2e4317/packages/boot/app-boot/tests/plugin-compatibility.spec.ts) define the rules:

- A declared `engines` must be an object. Its `dsh` member, when present, must be a string and decides compatibility alone, even when peers are malformed or disagree. Other engine members have no admission effect.
- An absent `engines.dsh` falls back to the existing DSH peer checks. All peer values must be strings before filtering to the DSH family. Cordis peers remain unrelated.
- Engine ranges use the existing npm semver adapter with prereleases included. Empty, malformed and `workspace:` engine ranges are unmet; only peer `workspace:^`, `workspace:~` and `workspace:*` resolve to the running version.
- A mismatch requires nonblank name/version strings. Their original spelling is retained. Exact exemptions still use the package name/version and original running version, including build metadata. The existing explicit NuGet name adapter remains the only case normalization; version strings are not normalized. Build approval and version exemption remain independent.

`DshPluginCompatibility.Peers` is renamed to `Requirements`, including the positional constructor and deconstruction parameter. The dictionary type and positional order are unchanged. A result contains either `engines.dsh` or mismatching peer names. Consumers using `Peers`, named arguments or serialized property names must migrate and rebuild; no alias or second result type is retained. `EvaluateCompatibility` and admission method signatures are unchanged. The management Remote DTOs do not expose this record, so their wire schemas and generated client signatures are unchanged. Their existing diagnostic strings now identify unmet requirements, including `engines.dsh`.

NuGet `cordis.plugin.json` engines and peers are preserved without filtering in both inspection metadata and the deployed `package.json`, including invalid values so admission can reject them. Known incompatibility is refused before SDK preparation even for disabled installation. The prepared manifest is checked again. Named bundles, pre-import entry checks, refresh/reconciliation, restart, exact grants and revocation share the same evaluator. Generic loaders and profiles without an explicit DSH runtime remain independent of this policy. This preserves the existing CLR metadata-locator and preparation/publication adaptations; it does not add Node package execution or change install/update lifecycle semantics.

The grant-file lock now recognizes macOS `EAGAIN` (35) as contention alongside the previously supported codes. This fixes waiting/cancellation for the same exact-grant persistence path; it does not broaden retries for unrelated macOS I/O errors or change the grant file format. Dictionary entries stand for own JSON fields; JavaScript prototypes and implicit installed-runtime discovery have no CLR equivalent because the host supplies `DshRuntimeIdentity` explicitly. Native diagnostic wording and exceptions remain .NET adaptations.

The verification repair extends the existing package-process owner to macOS. Native `posix_spawn` creates a suspended leader in its own process group; the owner records that group before resuming execution, reaps the direct child and drains both output pipes. Cancellation kills the group and waits for its live members to exit. A successful SDK exit with a surviving descendant is refused and cleaned up, including descendants that redirect their pipes or outlive the leader. This is process lifetime ownership, not isolation of untrusted build code: deliberate process-group escape is outside the contract. macOS, like Linux, does not promise automatic descendant termination when the host crashes; surviving groups block later preparation through the retained record. Legacy macOS records without group identity require explicit recovery. Unreadable/ambiguous membership remains a failure, while kernel zombies are already unable to execute. No public API is added. Platform constants and ABI are checked against the macOS SDK headers and [Apple's spawn attributes](https://developer.apple.com/library/archive/documentation/System/Conceptual/ManPages_iPhoneOS/man3/posix_spawnattr_setflags.3.html).

See [validation](validation.md) for executed evidence, including candidate source tests recorded separately from the formal baseline inventory.

## Numeric enum projection, 2026-10-16

Non-null constants assigned to nullable enums retain the underlying enum identity; null and nullable `default` remain null. This applies to authored bindings, parameter defaults and ordinary/reference data initializers. Independent emitters use their generated enum type, without carrying an author assembly dependency.

The fixed DSH analyzer retains enum declarations, while its [Zod emitter](https://github.com/deepseek-ai/deepseek-harness/blob/639ed015397290b3745d163aafe02ffee4aa3f84/packages/typert/generator/src/emitter.ts) explicitly refuses enum projection. Numeric CLR enum support is a .NET platform adaptation, not an upstream schema guarantee. The existing common model already records underlying types and member constants. Independent Remote, event and ordinary data projections reuse those facts without loading provider assemblies or introducing another saved format.

The default [.NET 10 STJ enum converter](https://github.com/dotnet/runtime/blob/v10.0.0/src/libraries/System.Text.Json/src/System/Text/Json/Serialization/Converters/Value/EnumConverter.cs) reads and writes underlying integers, including unnamed values, and exports an integer schema. Saved-model Web output uses that same schema through the shared client emitter without a member whitelist. Generated .NET declarations retain names, constants, underlying widths and Flags; native deserialization checks range. Nullable enums retain their null alternative, and enum defaults refer to the generated type. String enum policies and authored enum converters remain explicit static projection refusals. JavaScript number precision has its existing limits; this does not introduce lossless 64-bit transport.

## Linux package process completion, 2026-10-16

The fixed DSH manager waits for its interrupted tool before reporting cancellation. The existing .NET SDK process owner also requires termination and pipe settlement. On Linux, a process group can still exist solely because terminated descendants await reaping by another parent. The owner now checks `/proc` group state before treating that presence as unfinished execution. Only observed dead members with no remaining threads are discounted; live members, unreadable state and unconfirmed pipe settlement still prevent success. The same check protects reservation takeover. It does not reap another owner's children, expand cancellation into success after cleanup failure, or add a process supervisor. See [Linux process states](https://man7.org/linux/man-pages/man5/proc_pid_stat.5.html) and [wait semantics](https://man7.org/linux/man-pages/man2/waitpid.2.html).

A focused execution at `639ed015397290b3745d163aafe02ffee4aa3f84` observed the same result with a base-owned host group; reopening then produced duplicate retained rows. This is a shared defect, not an upstream guarantee of source preservation. The .NET correction checks the entry's existing ancestor removal intent before treating owned child cleanup as self-disposal. It does not reorder Fiber cleanup, suppress explicit Include writes, clear queued writes or change genuine self-disposal persistence. Standard bundle withdrawal persists profile selection without copying the composed tree into its base source.

Bundle protection and activation requirements apply the existing patch composer to the captured base and ordered candidate layers, then select reachable row objects contributed by that bundle's patch sources. External containers retain their position and later config replacement semantics. This is a detached audit of existing configuration facts; no provenance registry or second patch algorithm is introduced. Declaration rows remain a separate inventory view.

## Output contract reuse, 2026-10-14

The fixed DSH public `InvocationDescriptor` exposes its result codec, whose strict `create()` exposes a parseable schema ([protocol types](https://github.com/deepseek-ai/deepseek-harness/blob/639ed015397290b3745d163aafe02ffee4aa3f84/packages/typert/protocol/src/types.ts)). This supports composing the result contract; it does not prescribe a .NET JSON Schema property. The .NET adaptation exposes the existing output projection through non-virtual `TypertCodec.ResultSchema`, leaving internal directional dispatch internal. STJ input/output differences require this distinction from `Schema`. Consumers reuse the same projection as output decoding and client generation and choose validation timing themselves. No external override extension, schema service, HTTP endpoint or Gateway validation policy is added. See [authoring](authoring.md) for projection limits.

Output JSON presence is checked by ResultSchema before native reading. The output metadata modifier retains required assignments only for members with setters; getter-only values follow the author's native STJ construction. Constructor-parameter requiredness remains governed by the output projection, so a conditionally omitted output does not regain input-only requiredness. Native input metadata and output Schema generation are unchanged. This corrects the prior adapter's invalid required-but-not-deserializable metadata, not an inherent STJ refusal of readonly DTOs.

Generated TypeScript modules expose read-only `resultCodecs[endpoint].parse(value)` for decoded output values. The shared emitter compiles the existing output projection and actual serialization metadata into predicates; runtime descriptor export and supported saved-model projection use this same emitter. Only actual default `byte[]` metadata maps to `Uint8Array`. A base64 annotation or custom converter does not establish an attachment. `ResultSchema` continues to describe JSON before attachment extraction, independently of the executable decoded-value contract.

The decoded representation is checked separately from Boolean Schema constraints. The fixed DSH [generator](https://github.com/deepseek-ai/deepseek-harness/blob/639ed015397290b3745d163aafe02ffee4aa3f84/packages/typert/generator/src/emitter.ts) composes typed contracts with `z.intersection` and represents bytes with `z.instanceof(Uint8Array)`; the .NET emitter expresses its existing JSON Schema constraints over metadata-adapted values. A redundant `not: { type: "null" }` inside `allOf` must not reimpose pure JSON on bytes already identified by metadata, including nested bytes. JSON-only positions still reject typed arrays; composition does not widen their representation. This corrects the result emitter's predicate composition, without changing the fixed DSH strict-decoder policy or the public codec contract.

Fixed DSH [client invocation](https://github.com/deepseek-ai/deepseek-harness/blob/639ed015397290b3745d163aafe02ffee4aa3f84/packages/api/gateway/src/client/index.ts) runs a strict result decoder after Connection reconstruction and cancellation checks when that decoder exists. Generated .NET-port TypeScript unary callers likewise apply the decoded-value codec automatically for results with binary metadata. A mismatch becomes `gateway/internal` with the local `TypeError` as cause. Remote errors, cancellation and withdrawal keep their existing order and outcomes. Ordinary JSON results retain their existing automatic-validation policy; applications can explicitly call the exported codec. Stream item policy is unchanged. No staged acceptance API before attachment reconstruction is added: fixed DSH also awaits Connection reconstruction. Acceptance, unknown outcomes and receipt recovery remain application responsibilities. See [authoring](authoring.md) for the supported projection and standalone use.

## Upstream fidelity requirement

The saved-model backends recognize the framework identity of `System.Guid` as a .NET scalar adaptation. The fixed DSH [Schema emitter](https://github.com/deepseek-ai/deepseek-harness/blob/639ed015397290b3745d163aafe02ffee4aa3f84/packages/typert/generator/src/emitter.ts) distinguishes standard types from authored declarations; it does not define a CLR Guid API. The platform basis is the default STJ [Guid converter](https://github.com/dotnet/runtime/blob/v10.0.0/src/libraries/System.Text.Json/src/System/Text/Json/Serialization/Converters/Value/GuidConverter.cs), which reads/writes a JSON string and reports string/uuid Schema. Common facts keep the actual assembly/type identity. Data, method and event projections share the framework classification; independent C# retains Guid and Web uses string. Guid? and supported collection values follow existing null/presence rules. Host STJ remains responsible for value admission; no extra UUID version/variant validator is introduced. Custom converters remain refused by independent backends, external DTOs still need source facts, and this does not add Guid dictionary keys, ID wrappers or other BCL types.

Cordis.NET is a faithful, idiomatic .NET port of the fixed DSH baseline and the repository's agreed generic application infrastructure. Its own experimental designs do not establish a separate framework specification or a permanent compatibility obligation. The normative sources are the fixed upstream behavior, the agreed repository scope, and .NET adaptations supported by a concrete platform need.

Published alpha.5.2 is the public-use baseline for repository maintenance. Organizational cleanup preserves its APIs, generated contracts and package layout. A genuine correction must describe affected consumers and any necessary migration; preview status alone does not justify a breaking change.

Current code, API snapshots, generated clients and tests must be corrected against those sources. A signature's presence on main, an earlier public release or a passing old test does not by itself justify preserving an incorrect port. Correct errors and migrate their consumers directly. Retain a compatibility route only when an independent consumer or compatibility commitment requires it. Protect persisted data and Git history separately from obsolete runtime interfaces. This policy does not require line-by-line TypeScript translation or authorize rewriting mechanisms that already satisfy their contract.

Direct Gateway invocation follows fixed `packages/api/gateway/src/index.ts` `operatorPeer()`: an explicitly admitted carrier Peer wins; otherwise read the current `connection` service, or lazily reuse a Peer owned by the Gateway's Context. Native hosts construct `TypertHostConnection` and publish it with `owner.Provide("connection", connection)`, using ordinary Cordis service ownership. They withdraw that registration and dispose the Connection together. Streams capture the selected Peer once and retain it through iteration and cleanup; subsequent calls observe replacement or withdrawal. The former absence of Peer on direct calls was an incomplete port, not a platform adaptation. This does not establish the remaining rich Peer/scope-targeting workflows.

The ordinary data backend accepts `Dictionary<string,T>`, `IDictionary<string,T>` and `IReadOnlyDictionary<string,T>` through the existing common declaration composition and shared framework projection. JSON object keys remain strings; no numeric-key conversion is inferred. Values retain declared nullability, defaults and referenced declaration identities. This is a bounded static DTO/STJ projection, not generic author-code execution or support for arbitrary CLR collections.

Upstream fidelity is a project compatibility requirement. Evaluate changes against the fixed DSH revision in `upstream.lock.json`, its actual production callers, and their observable behavior. Check timing, ownership, lifecycle, failure and recovery boundaries, including the caller's use of the underlying mechanisms. Classify every difference as a necessary platform adaptation or an explicit project decision, and provide focused evidence for that difference. Passing tests that only establish a wrapper's internal consistency cannot, by themselves, demonstrate upstream fidelity.

## Deployment boundaries

The optional browser module bootstrap forwards shell-owned `staticModules` and optional `loadBundle` to the fixed DSH module system. Native catalog capture accepts the same additional exact request names; SDK defaults remain available. A package root does not supply arbitrary subpaths. The shell owns objects and types, while Cordis owns plugin effects. Default and custom transports retain the existing same-origin revision boundary. This restores the upstream bootstrap seam without adding a module registry or npm resolver; see [development](development.md#shell-owned-client-modules).

Browser startup reuses the fixed web activation audit; later sync retains diagnostic/retry semantics. Generated notification recovery reuses the fixed connection controller with a numeric timing adapter instead of the Schemastery runtime. Transient connection loss preserves plugins; explicit close withdraws them. CLI arguments, readiness and bounded exit reuse Composition, ProfileSession and Generic Host. These restore upstream assembly responsibilities without changing Core Pending semantics.

Browser `ClientEntries` has a local correction to fixed DSH `packages/client/modules/src/client/entries.ts`. Required structured references and provenance are part of the one current model contract. Incomplete and obsolete inputs are rejected with a re-extraction diagnostic; there is no historical-format reader, conversion or legacy projection. Identity validation checks present facts and cannot recover omissions or establish complete authored JSON behavior. Maintained consumers are re-extracted and rebuilt. No speculative compatibility commitment to experimental models justifies a second public route.

## Metadata numeric directions, 2026-10-15
