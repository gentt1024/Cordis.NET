## Reuse judgment

The existing implementation already uses Roslyn, System.Text.Json and ASP.NET Core. Retaining those dependencies is the strongest current choice. Additional libraries can reduce schema, DTO or carrier work, but none supplies the Cordis ownership contract.

| Candidate | Verified library capability | Fit and semantic boundary |

## Generation and runtime boundaries

Build-time reflection inside a generator/tool does not itself prevent the emitted application from using Native AOT. Runtime assembly loading and `Reflection.Emit` are [excluded by Native AOT](https://learn.microsoft.com/en-us/dotnet/core/deploying/native-aot/). Generated DTOs still need compatible runtime serialization.

Keep the existing explicit author `JsonSerializerContext`. [Ordinary source generators see the same input compilation](https://github.com/dotnet/roslyn/blob/ad34e675fc51beef49d66cb8005af3752895727d/docs/features/source-generators.md), not each other's ordinary outputs. Newly documented pre-compilation generation accepts non-compilation inputs only. It does not prove same-pass metadata generation from discovered author methods on the pinned SDK. Automatic context emission would need a separately assessed build arrangement.

## Semantics that remain Cordis-owned

No evaluated library replaces atomic Fiber-owned registration, exact-owner withdrawal, retained definition history, live service authority, Context selection/object lookup or definition/provider generation fences. These come from the fixed [registry](https://github.com/deepseek-ai/deepseek-harness/blob/639ed015397290b3745d163aafe02ffee4aa3f84/packages/typert/registry/src/service.ts), [Gateway](https://github.com/deepseek-ai/deepseek-harness/blob/639ed015397290b3745d163aafe02ffee4aa3f84/packages/api/gateway/src/index.ts) and explicit [native adaptations](compatibility.md#native-typert-contracts-and-carrier). Retain them behind any reused carrier.

[HttpClient cancellation](https://learn.microsoft.com/en-us/dotnet/api/system.net.http.httpclient.sendasync?view=net-10.0) can cancel the client's HTTP operation and lose a response. It cannot redefine Host invocation semantics or force business termination. The fixed [unary invocation](https://github.com/deepseek-ai/deepseek-harness/blob/639ed015397290b3745d163aafe02ffee4aa3f84/packages/api/gateway/src/index.ts#L361) preserves successful business results after abort and maps an invoked failure under abort to cancellation. Cancellation, withdrawal and generation validity remain separate.

Collectible ALC unloading requires releasing [external strong references to plugin types/instances](https://learn.microsoft.com/en-us/dotnet/standard/assembly/unloadability). Inference: host-held typed clients, DTO metadata, delegates, proxy targets or serializer resolver chains can retain a provider generation. Generate caller DTOs or use reviewed host-shared contract assemblies instead of referencing unloadable provider implementations. Generation-local metadata must retire with its owner. These design choices are candidates, not implemented unload guarantees.
